Send a file to the device next to you.

No account, no upload, no “sign in to continue”. ZenShare talks straight to the other device over the network you are already on — encrypted end to end, and verified chunk by chunk before anything reaches your disk.

Encrypted, not “encrypted”

QUIC with TLS 1.3 on every transfer. There is no plaintext mode to accidentally leave on.

Verified before it lands

Every 4 MiB chunk carries a BLAKE3 hash. A corrupt chunk is refused, not written.

Nothing in the middle

No server, no account, no analytics. The only packets that leave your machine go to the device you picked.

What does not work yet

Android can receive, not send. The APK launches, finds peers on the same Wi-Fi and receives files into app-scoped storage you can reach over USB. Picking a file to send needs Android's Storage Access Framework, which is the next piece of work. The UI says so rather than showing a dead button.

No iOS build. Same port as Android, plus a sandbox that forbids the multicast trick discovery relies on.

No browser version, and there cannot be one. Browsers cannot open a raw UDP socket, and QUIC needs one. A web app would require a relay server in the middle, which is the exact thing this project exists to avoid.

The six-digit pairing screen is not wired up. Transfers are encrypted, but first contact with a stranger on a shared network is not yet confirmed by a code you compare. Do not use it on public Wi-Fi to send something you would not email.

Discovery can be blocked. Some guest and corporate networks drop multicast. The app runs; it just will not list the other device.
